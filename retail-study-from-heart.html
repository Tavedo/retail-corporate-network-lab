LAN concepts

The campus half — how one building's network is carved up and glued back together.

What is a VLAN, and why use one?VLAN
tap — say it first

A VLAN splits one physical switch into several separate virtual networks. Staff, POS, cameras and guests can share the same switches but be completely isolated at Layer 2 — different broadcast domains, different subnets.

Analogy: one office building partitioned into separate departments — same building, same corridors, but each floor is sealed off and private.
Say it: "A VLAN is a logical network on shared switches. In the store it lets me keep POS, staff, guest WiFi and cameras separate for security, without buying separate switches for each."
If VLANs are isolated, how do two of them talk?Routing
tap

They can't on their own — they need a router or a Layer-3 switch. The L3 switch has a virtual interface (an SVI, interface Vlan20) in each VLAN, acting as that VLAN's gateway. Traffic between VLANs goes up to the SVI, gets routed, comes back down.

Analogy: VLANs are sealed rooms; the L3 switch is the hallway connecting them. No hallway, no way between rooms.
Say it: "VLANs are separate subnets, so they need Layer-3 routing to talk. On the HQ core I use SVIs — a virtual gateway interface per VLAN on the L3 switch — and enable ip routing. That's inter-VLAN routing."
Router-on-a-stick vs L3-switch inter-VLAN routing?Design
tap — you used both

Same goal, two methods. L3 switch (HQ): SVIs do the routing in hardware — fast, for a site with a core switch. Router-on-a-stick (branch): one physical link to the switch carries all VLANs as a trunk, and the router splits them with subinterfaces (G0/1.20, G0/1.30), one per VLAN. Cheaper, for a small site with no L3 switch.

Analogy: the L3 switch is a multi-lane interchange (fast, built-in). Router-on-a-stick is one road with painted lanes — a single link doing the job of many by tagging.
Say it: "At HQ I used SVIs on the L3 core — fast hardware routing. At the branch there's no L3 switch, so I used router-on-a-stick: one trunk to the router, subinterfaces per VLAN. Same result, right tool for each site's size."
What's a trunk, and what does 802.1Q do?Switching
tap

A trunk is a link that carries many VLANs between switches (vs an access port = one VLAN for an end device). 802.1Q is the tagging standard — it stamps each frame with its VLAN number so the far end knows which VLAN it belongs to.

Analogy: a multi-lane highway where every car wears a sticker saying which lane (VLAN) it's in, so the next junction sorts it correctly.
Say it: "A trunk carries multiple VLANs on one link; 802.1Q tags each frame with its VLAN ID so both ends keep them separate. Access ports face end devices and carry a single VLAN, untagged."
What does OSPF do here, in one line?OSPF
tap

It's the dynamic routing protocol between HQ and the branch. The routers tell each other which networks they can reach and automatically recompute when something changes (like a WAN link dropping). No static routes to hand-maintain.

Analogy: GPS that reroutes itself — when a road closes, it finds the next-best way with no one touching it.
Say it: "OSPF shares routes dynamically between the sites and reconverges on its own if a link fails. That's what makes my WAN failover automatic — I didn't have to script anything."
NAT / PAT — what and why?NAT
tap

Private internal IPs (10.x) can't go on the internet. PAT (NAT overload) translates all of them to the one public IP on the HQ router, tracking each with a port number so replies come back to the right device.

Analogy: an office switchboard — hundreds of internal extensions, one public phone number; the switchboard remembers who's on which call.
Say it: "PAT lets every internal device share the one public IP on the HQ router for internet access, using port numbers to keep sessions apart. The branch reaches the internet through HQ."
What problem does STP/RSTP solve?STP
tap

Switches with redundant links form loops, and Layer-2 loops are catastrophic (broadcast storms melt the network). Spanning Tree detects the loop and blocks a redundant port, leaving one active path; if the active path dies, it unblocks the backup. RSTP is the fast version. PortFast skips the delay on access ports (no loop risk from a PC).

Analogy: a traffic cop blocking one of two roads that form a circle, so cars don't loop forever — and waving the backup road open the instant the main one closes.
Say it: "STP prevents Layer-2 loops by blocking redundant links until they're needed. RSTP converges fast; PortFast puts access ports straight into forwarding since a PC can't cause a loop."

Security & PCI — the retail difference

Segmentation is where a retail network earns its keep. This is the stuff that separates you from someone who just knows VLANs.

Why isolate the POS network? (the PCI question)PCI
tap — know this cold for retail

The POS handles cardholder data, which falls under PCI-DSS. The rule: the card-data environment must be segmented so it only touches what it needs. So POS can reach the payment/inventory servers and nothing else internal — not staff PCs, not cameras, not guest WiFi. Smaller attack surface, smaller audit scope.

Analogy: a bouncer with a short list — POS is allowed into the server room and out the front door, but no other room in the building.
Say it: "POS handles card data, so under PCI I segment it — my ACL lets POS reach only the payment servers and block the rest of the internal network. It shrinks the breach surface and keeps the compliance scope small."
How does the Guest-WiFi isolation ACL actually work?ACL
tap

Applied inbound on the guest SVI: deny guest → any internal (10.0.0.0/8), then permit guest → any (the internet). First match wins, so internal is blocked but the internet still flows.

ip access-list extended GUEST-ISOLATION deny ip 10.40.40.0 0.0.0.255 10.0.0.0 0.255.255.255 permit ip 10.40.40.0 0.0.0.255 any
Say it: "Guest WiFi gets internet but nothing internal. The ACL denies guest-to-internal first, then permits guest-to-anything — so the only thing left after the deny is the internet."
Be honest — is your POS ACL fully PCI-compliant?Nuance
tap — the mature answer

It's PCI in principle, not PCI-tight. Your rule permits POS → servers, denies other internal, then permit ... any for the internet. True PCI wants POS outbound restricted to only the payment processor, not the open internet.

Say it (this impresses): "I scoped POS to the servers and blocked other internal VLANs. To be fully PCI-compliant I'd tighten the outbound rule to only the payment gateway's addresses, not permit the whole internet — right now it's the correct principle, not the final hardening."

Admitting the limitation shows more understanding than pretending it's perfect.

What else should be isolated that currently isn't?Gap
tap

The cameras / IoT VLAN (50). IP cameras are a classic breach vector — they should be locked down like the POS: reach only their NVR/recording server, nothing else. You isolated Guest and POS; a CAMERA-ISOLATION ACL would complete the story.

Say it: "I'd add the same treatment to the camera VLAN — IoT devices are a common entry point, so they should only reach their recorder and be blocked from everything else internal."

WAN resilience — the gap you closed

This is your strongest material: you found the weak spot and fixed it twice over. Own every card here.

What was the gap, and why does it matter for retail?The why
tap

One WAN link from the store to HQ, and the branch backhauls everything (even internet) through it. If it drops, the store can't reach the servers → the POS can't take card payments → lost sales. For retail, WAN uptime is revenue.

Say it: "The store had a single WAN link — a single point of failure. In retail that's critical, because if the tills can't reach HQ they can't process payments, so I built in a backup path with automatic failover."
How does the failover actually work?Failover
tap

A second WAN path, with OSPF cost making it a backup: primary link = low cost (preferred), backup = high cost (100). OSPF uses the primary; if it drops, OSPF detects it, recomputes, and moves traffic to the backup in a few seconds — losing only 2–3 packets.

Analogy: OSPF cost is a toll price — everyone takes the cheap road; the expensive one carries traffic only when the cheap one is closed.
Say it: "I added a second path and used OSPF cost to make it a backup — high cost so it sits idle. When the primary fails, OSPF reconverges onto it automatically. A continuous ping drops a couple of packets then keeps flowing."
Why is "two links" not enough — what's diverse transport?Design
tap

Two links between the same two routers prove failover, but if they use the same provider or fibre path, one cut or one provider outage still kills both. Diverse transport = the backup rides a different provider — e.g. primary leased line + backup over broadband internet. That's what you upgraded to.

Say it: "True resilience means diverse transport — the backup should use a different provider, not just a second cable to the same place. So I made the backup an internet path, independent of the primary circuit."
Why GRE *and* IPsec on the backup? (classic question)VPN
tap

The backup rides the public internet, so it must be encrypted (IPsec). But IPsec alone only carries unicast — it can't carry OSPF (which uses multicast). GRE is the envelope that carries anything, including OSPF; IPsec locks that envelope. Run OSPF inside the GRE tunnel, and failover works over an encrypted path.

Analogy: GRE is the ride, IPsec is the lock. GRE carries the routing; IPsec stops anyone reading it.
Say it: "GRE carries the routing protocol — IPsec can't carry OSPF's multicast on its own. So GRE tunnels OSPF across the internet and IPsec encrypts it. GRE for the ride, IPsec for the lock."
What's recursive routing, and how did you avoid it?Gotcha
tap — advanced, impressive

If a router learns how to reach the tunnel's destination through the tunnel itself, the tunnel tries to route over itself and flaps down — %TUN-5-RECURDOWN. You avoid it by making sure the tunnel endpoint is reachable over the physical transport only (kept the transport subnet connected, not advertised into OSPF over the tunnel).

Say it: "Recursive routing is when the tunnel destination is learned via the tunnel — it collapses. I kept the underlay reachability outside the tunnel, so the tunnel endpoint is always resolved over the physical link, never through itself."
Give the whole retail-WAN story in 20 seconds.The pitch
tap
Say it: "The store had a single WAN link — if it failed the tills couldn't take payments. I added a backup path and used OSPF cost so it fails over automatically. Then I made it diverse transport — the backup is an encrypted GRE/IPsec VPN over broadband internet — so even a full provider outage on the primary keeps the store trading. Failover drops only a couple of packets."

That's a complete, senior-sounding answer: problem → fix → why → proof.

Interview Q&A

Enterprise/CCNA-level questions you'll actually get. Answer out loud, then check.

"How do devices in two different VLANs communicate?"Q
tap
Model: "They can't at Layer 2 — VLANs are separate subnets. You need Layer-3 routing: either SVIs on a Layer-3 switch, or router-on-a-stick with subinterfaces. In this lab the HQ core uses SVIs; the branch uses router-on-a-stick."
"What's the difference between an access port and a trunk?"Q
tap
Model: "An access port carries one VLAN and faces an end device, untagged. A trunk carries multiple VLANs between switches and tags each frame with 802.1Q so both ends keep them separate."
"How would you make a branch store's connectivity resilient?"Q
tap
Model (use yours): "A second WAN path with dynamic-routing failover — I used OSPF cost so the backup only carries traffic when the primary drops. For real resilience I'd make it diverse transport: a backup over broadband internet as an encrypted GRE/IPsec VPN, so a single provider outage can't take the store down. Critical in retail because the POS can't stop."
"Why segment the POS network?"Q
tap
Model: "PCI-DSS. The cardholder-data environment must be isolated, so POS reaches only the payment servers and nothing else internal. It shrinks the attack surface and the audit scope. I'd tighten outbound to just the payment gateway for full compliance."
"Walk me through what happens when the primary WAN fails."Q
tap
Model: "OSPF loses the neighbour on the primary, removes those routes, and recomputes using the backup path, which had a higher cost so it was idle. Within a few seconds traffic flows over the backup — a continuous ping loses two or three packets. When the primary returns, the lower cost makes it preferred again."
"Why do you need GRE if you already have IPsec?"Q
tap
Model: "IPsec on its own only protects unicast — it can't carry a routing protocol like OSPF, which uses multicast. GRE tunnels the routing (and anything else) and IPsec encrypts the GRE. GRE for the ride, IPsec for the lock."
"Tell me about something you built and improved." (behavioural)Q
tap
Model: "I built a two-site retail network — HQ and a store over a WAN, with VLAN segmentation and POS isolation for PCI. Reviewing it, I spotted the store had a single WAN link, which for retail means the tills go down if it fails. So I added a backup path with OSPF failover, then upgraded it to diverse transport — an encrypted GRE/IPsec VPN over broadband internet. I tested it with a continuous ping through a link failure and lost only a couple of packets."
